# 행동 전략

점수를 만드는 건 결과물보다 **내가 AI를 다루는 모습**이에요. 행동 하나하나가 공식 평가 항목의 증거로 남게 움직여요.

## 이전 대회 1등이 밝힌 방식 (우리 키트 흐름과 같아요)
"바로 코딩하는 대신 먼저 도메인 담당자에게 실제로 어떻게 일하는지, 어떤 피드백이 유용한지 물었다. 그다음 **한 번에 사용자 행동 하나와 성공 기준 하나**만 다뤘고, 작은 조각을 만들어 자동 검사를 돌린 뒤 **실제 화면에서 테스트하고 나서야** 다음으로 갔다. 각 AI에게 **명확한 역할**을 줬다."
제작진은 요구사항에 없는 과한 방어 설계(오버엔지니어링)를 지적했고, 숙련자일수록 토큰 비용이 낮았다고 했어요.

## 원칙 8개
1. **판단은 내가, 이유는 내 말로.** 단계를 넘길 때마다 결정, 이유, 버린 대안을 내 말로 써요. AI 제안을 그대로 받아도 왜 받는지 한 줄 붙여요. → 문제 정의, 의사결정, 역할 배분
2. **첫 25분에 문제를 정확히 잡아요.** README는 AI보다 내가 먼저 읽어요 (5분). 첫 프롬프트에 내 이해를 2~3줄로 쓰고, DM으로 빈칸을 채우고 합의를 확인해요. 틀린 문제를 완벽하게 푸는 게 가장 큰 감점이에요.
3. **지시는 구조 있게.** 목표 / 조건 / 완료 기준 / 범위 / 금지 + 이유. 짧아도 빠짐없이. → AI 지시 품질
4. **위임은 범위를 정해서 하고, 판단은 내가 쥐어요.** 구현은 스펙 단위로 worker에게, 원인 찾기는 explorer에게, 독립된 일은 병렬로. → 역할 배분, 시간 안배
5. **검증은 내 손으로도 해요.** 터미널 세션도 수집되니까, 별도 터미널 탭에서 테스트와 curl을 내가 직접 돌려요. AI가 "통과"라고 한 걸 내가 다시 확인한 기록이 남아요. 표본 검산과 내장 Browser 클릭도 직접 해요. → 결과 검증
6. **AI를 고치는 순간을 숨기지 않아요.** 틀린 게 보이면 무엇이 어떤 근거와 어긋나는지 짚고, 원인부터 찾게 한 뒤 재발 방지 테스트를 붙여요. 오류 복구로 기록해요. → 반복 개선, 오류 복구, Cognition
7. **AI 결과마다 판정 한 줄.** 받아들임·고침·버림과 근거(내가 돌린 명령과 결과)를 내 말로 말해요 ([P3.5](prompts.md)). 확인 문제는 제출 문서의 항목을 ID로 짚어서 "무엇을 받아들이고 고치고 버렸나, 근거는?"을 물어요. → 반복 개선, 결과 검증, 설명
8. **시간을 내가 관리해요.** 체크포인트를 지키고, AI가 도는 동안 다른 일을 하고, 사고가 나면 3분 안에 대안으로 넘어가요. → 시간 안배, 효율

## 코치 창 쓰는 법 (터미널 2)
- 메인이 일하는 동안 코치 창에서 생각해요: `상황`, `설명 <함수>`, `반론`, `질문해줘`, `DM 점검`.
- 코치는 선택지와 대가를 보여주지만, **메인에 보낼 문장은 내가 내 말로 써요.** 코치가 쓴 문장을 복사하면 기록상 다시 승객이 돼요.
- 코치에서 얻은 근거로 결정하면 메인 프롬프트에 "코치와 검토한 결과 X는 Y 때문에 버림"처럼 이유를 남겨요.

## 시험장 조작 사고 막기
- **브라우저 단축키 주의:** Cmd+W는 시험 탭을 닫고, Cmd+Q는 Chrome을 끄고, Cmd+R은 저장 안 된 내용을 날려요. 로컬 에디터 습관대로 누르지 마세요. 탭이 닫히면 같은 링크로 재접속하고, 카메라·화면 공유·Proctor QR을 다시 연결해요.
- **Codex 터미널:** Ctrl+C는 실행 중인 작업을 끊어요. 여러 줄 프롬프트는 붙여넣기로 넣고, 줄바꿈 키가 안 먹으면 한 줄로 써요.
- **컨텍스트 잔량:** Codex 상태 표시에서 컨텍스트가 40% 아래로 남으면 handoff 해요. 자동 요약을 기다리지 않아요.
- **승인 요청:** "승인 대기"는 기다린다고 진행되지 않아요. 터미널을 자주 보고 바로 판단하세요. sub-agent의 승인 요청도 같은 곳에 떠요.
- **헷갈리면 바로 Helper:** UI나 제출 방법이 막히면 혼자 헤매지 말고 바로 Helper에게 물어요.

## 확인 문제 행동
결론 문장부터 써요 (시간이 끝나면 자동 확정). 그다음 하위 질문마다 한 문장씩, 질문의 단어를 앞에 붙여 써요. 파일명이나 함수명, 수치, J-id, 한계를 넣어요. 질문 전제가 틀리면 먼저 바로잡아요. 모르면 솔직히 쓰고 어떻게 확인할지를 써요.
