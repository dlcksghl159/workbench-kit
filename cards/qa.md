# 확인 문제 카드 (외워서 들어가기)

## 진행 (공식 가이드)
1. "제출하고 문제풀기" → 미리보기 → "제출물 확정하고 문제풀기". **확정하면 파일을 더 고칠 수 없어요.**
2. 문제 준비 대기: 최대 10분. 자동 재시도하면 대기가 다시 시작돼요. 이 시간은 답변 타이머가 아니에요.
3. 문항 수 확인 (응시 화면 기준, 안내상 6문항) → "문제 풀기"를 누르면 1번 타이머 시작.
4. 문항당 5분. **다음 문항 타이머는 직전 답안을 제출하는 순간 바로 시작돼요.** 쉬는 시간이 없어요.
5. 시간이 끝나면 지금까지 쓴 답이 자동 확정돼요. 그러니 핵심 문장부터 먼저 써 두세요.
6. AI, 외부 창, 복사·붙여넣기, 이전 문항으로 돌아가기 모두 불가. 직접 타이핑해요.
7. 마지막은 "답안 제출하고 마치기" → 완료 화면에서 제출 ID·시각·파일 수 확인.

## 준비는 시험 중에 해요
- 11:40에 `wb-examiner`가 규칙 한 장, 외울 것, 예상 문제를 만들어요 (`.kit/runtime/QA_DRILL.md`).
- AI가 도는 동안 A(규칙 한 장)와 B(외울 것)를 읽어요.
- 12:40에 갱신한 뒤 10분 드릴: 시나리오 문제를 하나씩 받아서 답 없이 직접 풀어요.
- 시나리오 문제는 규칙 + 계산이에요. 경계값(이하/미만), 단위, 반올림, 시간대, 정렬 순서를 숫자로 기억하세요.

## 4문장 공식
1. **결론**: "저는 ~하도록 구현했습니다."
2. **근거**: "[파일/함수]에서 ~하고, [테스트/검증]으로 확인했습니다."
3. **한계**: "다만 ~한 입력이나 상황에서는 ~할 수 있습니다."
4. **다음**: "그래서 ~를 추가로 검증하거나 ~로 개선하겠습니다."

## 질문 전제가 실제 구현과 다를 때 (가이드 공식 안내)
첫 문장: "질문의 전제와 실제 구현이 다릅니다. 실제로는 ~하도록 구현했습니다." 그다음 4문장 공식대로 써요.

## 자주 나오는 질문 유형
- 왜 이 구조나 방법을 골랐나 (버린 대안과 이유)
- 이런 입력이나 장애가 오면 어떻게 되나
- 가장 약한 부분과 그 영향
- 결과가 맞다는 걸 어떻게 확인했나
- AI가 만든 결과를 어떻게 검증하고 고쳤나
- 보안·데이터 위험
- 시간이 더 있으면 무엇을 하겠나

## 꼭 나올 수 있는 질문: "AI를 어떻게 썼나요?" (4문장 미리 준비)
1. "요구사항 정의와 판단은 제가 하고, Codex는 탐색·구현·리뷰·모의 채점 역할로 나눠 썼습니다."
2. "요구사항마다 R-id를 붙여 스펙, 테스트, 커밋, 보고서까지 연결했고, 위임할 때는 스펙 파일 하나만 넘겼습니다."
3. "AI 결과는 테스트와 표본 검산으로 직접 확인했고, [실제 사례: 예) C등급 누락]은 원인을 찾아 고쳤습니다."
4. "한계는 [시간 때문에 못 한 것]이고, 더 있었다면 [다음 검증]을 했을 겁니다."

## 5분 쓰는 법
- 30초 생각 → 1번 결론 문장부터 바로 쓰기 → 나머지 3문장 → 남은 시간에 다듬기.
- 파일명이나 함수명을 하나는 꼭 넣어요. 구체적일수록 좋아요.
- 모르면 추측하지 말고 "확인하지 못했다, 이렇게 확인하겠다"로 써요.
- **한글 마지막 글자 날림 주의:** 시간이 끝나 자동 확정될 때 조합 중인 마지막 글자가 빠질 수 있어요. 문장을 마침표와 띄어쓰기로 끝내는 습관을 들이세요.
