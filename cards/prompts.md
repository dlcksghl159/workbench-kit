# 프롬프트 카드 (메인 Codex 세션)

[ ] 안은 내 말로 채워요. 공식 기준 문구는 "AI에 **역할·맥락과 기대 결과**를 명확히 전달하는지"예요. 그래서 지시마다 역할(누가 할지), 맥락(왜, 어떤 조건), 기대 결과(완료 기준)가 들어가게 써요. 이전 대회에서 점수 차이가 가장 컸던 축이 바로 이 Intent예요.

## P0. 시작 (10:00~10:10)
```
wb-kickoff 스킬로 시작해.
내가 이해한 과제: [README를 읽고 2~3줄, 내 말로]
먼저 확인하고 싶은 점: [불명확하거나 걱정되는 점]
아직 코드는 수정하지 마.
```

## P1. DM 답변 반영 (~10:35)
DM_LOG.md에 답을 다 붙여넣은 뒤:
```
DM 끝났어. process/DM_LOG.md 반영해서 NOTES와 REQUIREMENTS를 확정안으로 갱신해.
우선순위 판단: [무엇이 Must인지와 그 이유]
답이 애매한 항목은 추가 질문을 하나씩 제안하고, 담당자에게 보낼 합의 확인 문장도 만들어줘.
```

## P2. 계획 (~10:45)
```
요구사항 확정됐어. wb-slice 스킬로 slice 계획 세워. 검증을 통과한 slice는 커밋해.
첫 slice에서 [입력 → 처리 → 출력]이 얇게라도 끝까지 돌아가야 해.
[기술 선택이나 시간 제약에 대한 내 판단]
pre-mortem도 포함해서 보여줘. 확인하고 시작할게.
```

## P3. slice 진행 (반복)
```
S[n] 진행해. 스펙 쓰고 wb-worker에게 맡긴 다음 결과를 직접 검증하고 기록해.
이번 slice에서 특히 지킬 조건: [DM 조건]
```

## P4. 판단을 바꿀 때
```
[무엇을 보고] 판단을 바꿀게: [이전 판단] → [새 판단]. 이유: [ ]
NOTES '판단 변경'에 기록하고, 영향받는 R-id·스펙·테스트를 같이 고쳐.
```

## P5. 오류가 났을 때
```
[증상]. 바로 고치지 말고 wb-explorer로 원인 후보 2~3개와 근거부터 찾아.
원인을 확정하면 고치고, 재발 방지 테스트까지 추가해. '오류 복구'에 기록해.
```

## P6. 세션 넘기기 (첫 end-to-end 완성 후, 방향 전환 후, 마무리 전)
```
wb-handoff 스킬 실행해.
```
새 세션에서:
```
process/HANDOFF.md를 읽고 이어서 진행해. '다음 행동'부터 시작해.
```

## P6.5 중간 점검 (첫 end-to-end 완성 직후, ~11:40)
```
wb-grader로 지금까지 기록을 채점해줘. 증거 없는 주장이랑, 15분 안에 할 수 있는 보완 3개만 보여줘.
```
보완은 실제로 실행하고 나서 기록해요. 실행 안 한 걸 썼다고 적으면 로그 교차 확인에서 걸려요.

## P7. 마무리 시작 (~12:15)
```
wb-finish 스킬로 마무리 시작해. 이제 새 기능은 금지야.
reviewer 결과를 보여주면 무엇을 고칠지는 내가 정할게.
```

## P8. 확인 문제 대비 (11:40에 1차, 12:40에 갱신)
```
wb-examiner로 예상 문제를 만들어줘. 규칙 한 장, 외울 것, 실제로 실행해서 답을 계산한 시나리오 문제, 짧은 4문장 답으로.
```
만들어지면 `.kit/runtime/QA_DRILL.md`의 A(규칙 한 장)와 B(외울 것)를 AI가 도는 동안 읽어요.

## P8.5 드릴 (12:40, 10분)
```
QA_DRILL.md의 시나리오 문제를 하나씩 내줘. 답은 보여주지 말고, 내가 답하면 규칙 한 장 기준으로 맞았는지와 빠진 점만 짧게 알려줘.
```
